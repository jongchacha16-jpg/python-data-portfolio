## 데이터

- `ds_salaries.csv` — 607행 × 12열. 완전 중복 42행을 제거하면 565행.
- 결측치 없음.
- 고카디널리티 범주형이 많다: `job_title` 50종(11종이 단 1건), `employee_residence` 57종(28종이 단 1건),
  `company_location` 50종(21종이 단 1건). `US`가 55~58%로 편중.
- `remote_ratio`는 연속형이 아니라 `{0, 50, 100}` 3범주. `employment_type`은 FT가 96.9%로 사실상 상수.

## 반드시 지킬 규칙

1. **타겟은 `salary_in_usd` 회귀로 프레이밍한다.** 33/66 분위수 3-class 분류는 임계값 근처를 임의로 가른다.
   과거 노트북이 분류로 푼 것은 **재검증에서 기각된 접근**이다.
2. **피처에서 제외**: `salary`(리키지), `salary_currency`(`company_location`과 중복), `Unnamed: 0`(인덱스).
   - `salary` + `salary_currency`를 함께 쓰면 통화별 환산비가 상수이므로 **타겟이 결정론적으로 복원된다.**
   - 단, **`salary_currency` 단독은 리키지가 아니다** — 중복 변수일 뿐이다. 이 구분을 뭉개지 말 것.
3. **모든 전처리는 `Pipeline`/`ColumnTransformer` 안에서 fold별로 fit한다.**
   전체 데이터에 `pd.get_dummies`를 먼저 적용하고 나중에 split하지 말 것.
4. **희소 범주(6건 미만)는 `Other`로 묶는다.** 묶는 기준 빈도도 훈련 fold에서만 계산한다.
   그러지 않으면 피처가 165개까지 늘어 행:피처가 3.4:1이 된다.
5. **성능은 5-fold 교차검증 평균 ± 표준편차로 보고한다.** 단일 `train_test_split` 결과만 보고하지 말 것 —
   seed만 바꿔도 R²가 0.22~0.65로 요동친다.
6. **베이스라인과 함께 보고한다.** 최소한 전체 평균 예측과 "경력 × 국가" 조회 테이블(R² 0.334) 대비 개선폭을 명시.
7. **회귀는 MAE·MAPE를 R²와 함께 보고한다.** R² 0.50은 실무 언어로 "평균 43% 오차"다.
8. `random_state=42`, `test_size=0.2` 고정.

## 현재 baseline (재검증 노트북 실측, 565행 5-fold CV)

| 모델 | R² | MAE | MAPE |
| --- | --- | --- | --- |
| 전체 평균 예측 | −0.001 | $53,348 | 124.4% |
| 경력 × 직무그룹 평균 | 0.204 ± 0.120 | $44,438 | 92.1% |
| 경력 × 국가 평균 | 0.334 ± 0.094 | $40,237 | 86.4% |
| Ridge (α 튜닝) | 0.493 ± 0.058 | $34,453 | 54.9% |
| **Ridge + `log1p` ← 채택** | **0.500 ± 0.069** | **$31,879** | **42.6%** |
| Ridge + `sqrt` | 0.509 ± 0.062 | $32,344 | 47.1% |
| RandomForest (튜닝) | 0.488 ± 0.074 | $33,318 | 50.5% |

- Ridge와 RandomForest는 **표준편차 안에서 구분되지 않는다.** 성능이 같으므로 해석 가능한 Ridge를 채택했다.
- 새 실험은 이 표와 비교해 개선 여부를 명시한다. 훨씬 높은 성능이 나오면 리키지를 의심할 것.

## 하지 말아야 할 것

| 금지 | 근거 |
| --- | --- |
| 3-class 분류를 1차 프레이밍으로 사용 | 임계값 임의성, 정보 손실 |
| `salary_currency`를 "리키지"라고 서술 | 중복 변수이지 리키지가 아니다 |
| IQR로 고연봉 이상치 제거 | 10건 전부 미국 실존 고위직. 설명 대상 자체를 삭제하는 것 |
| 고카디널리티를 그룹핑 없이 원-핫 | 165피처/565행 = 3.4:1, OLS R² 0.273±0.148로 붕괴 |
| 단일 split 결과로 모델 비교 | seed만 바꿔도 R² 0.43 요동 |
| 한쪽만 튜닝하고 모델 우열 판단 | 실제로 "Ridge 압승" 오판이 발생했다 |
| 계수 크기 비교 시 척도 미통일 | 순서형이 더미보다 과소평가된다 (`experience_level` 6위→1위로 바뀜) |
| PCA를 차원 축소 기본 수단으로 사용 | 95% 분산에 105개 성분 필요, R² −10 |
| 검증 없는 SMOTE/class_weight | 과거 노트북에서 정확도 0.5917→0.5583 악화 |
| 노트북 출력을 손으로 작성 | 실행 안 되는 셀에 결과만 표시되는 사태가 실제로 발생했다. `nbconvert --execute` 사용 |

## `MachineLearning_Team5.ipynb`의 알려진 문제 (보존용이므로 수정하지 않음)

- 셀 64·65의 `drop(columns=[...])`에 `salary_class_`가 빠져 실행 오류가 났던 문제는 **수정되었다.**
  (`salary_class_`는 타겟과 99.7% 일치하는 컬럼이라, 오류 없이 통과했다면 정확도가 99%로 튀었을 것이다.)
- 다만 일부 셀의 출력은 노트북 밖에서 계산되어 삽입된 것이라 **Restart & Run All 재현이 보장되지 않는다.**
- 리키지 서술이 부정확하고, 성능이 단일 split 기준으로 보고되어 있다.

→ 이 파일은 재검증의 "before" 기록으로서 그대로 둔다. 인용하거나 이어서 작업하지 말 것.

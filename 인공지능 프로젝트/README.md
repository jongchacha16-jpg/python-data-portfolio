# 사진 → 감정 → 이모지 매칭 (Photo-to-Emoji)

**사진 속 인물의 표정을 읽어 그 사람에게 맞는 이모지를 찾아주는 것**이 이 프로젝트의 목표입니다.

원래 구상은 사진으로 **나만의 이모티콘을 생성**하는 모델이었으나, 학습 데이터의 한계를 확인하고
**기존 이모지 중에서 골라주는 방식**으로 범위를 좁혔습니다. 이 판단은 옳았습니다 —
사진에서 *새로운* 이모지를 만들려면 (사진, 대응 이모지) 쌍 데이터가 대량으로 필요한데 그런 데이터셋은 없습니다.

| 단계 | 내용 | 상태 |
| --- | --- | --- |
| 0 | 사진 → **나만의 이모티콘 생성** | 데이터 한계로 축소 (아래 1~3으로 대체) |
| 1 | 사진 → **표정 분류** (7개 감정) | ✅ CNN 학습 완료 (검증 정확도 0.5628) / ⚠️ 가중치 소실 |
| 2 | 분류 결과 → **감정 수치화** | ✅ 1단계 softmax 출력이 곧 그것 — 이미 있었습니다 |
| 3 | 수치 → **대응 이모지 할당** | ✅ **완성** (`이모지_매칭_파이프라인.ipynb`) |

3단계는 2023년 당시 막혀 있었고, **2026-09-10에 완성했습니다.**
1단계 가중치만 복구하면 사진을 넣어 이모지가 나오는 완결된 파이프라인이 됩니다.

> **⚠️ 이 README는 2026-09-07에 정정되었습니다.**
> 이전 README는 이 프로젝트를 *"기한 내 목표를 완전히 달성하지 못했다 / 모델 학습까지 완료하지 못했다"*
> 고 서술했으나, **노트북을 실제로 열어 확인한 결과 모델은 완성되었고 20에폭 학습까지 끝나 있었습니다.**
> 실패한 것은 부가 시도였던 이모지 변환 하나였고, 그 실패 원인 진단도 틀렸습니다(아래 §실패한 부분 참고).

## 데이터

| 항목 | 내용 |
| --- | --- |
| 출처 | Kaggle — [`ananthu017/emotion-detection-fer`](https://www.kaggle.com/datasets/ananthu017/emotion-detection-fer) |
| 규모 | 훈련 **22,968장** / 검증 **1,432장** |
| 클래스 | 7개 — `angry`, `disgusted`, `fearful`, `happy`, `neutral`, `sad`, `surprised` |
| 형식 | 48×48 그레이스케일 |

증강: `shear_range=0.2`, `zoom_range=0.2`, `horizontal_flip=True`, 정규화 `1./255`

## 모델

```
Conv2D(32, 3×3, relu) → MaxPool(2×2)
Conv2D(64, 3×3, relu) → MaxPool(2×2)
Conv2D(128, 3×3, relu) → MaxPool(2×2)
Flatten → Dense(256, relu) → Dropout(0.5) → Dense(7, softmax)

optimizer=adam, loss=categorical_crossentropy, epochs=20
```

## 실패한 부분 — 이모지 변환 (그리고 원인 진단의 오류)

원래 구상은 학습한 모델을 **이모지 이미지**에도 적용해보는 것이었습니다.
이모지를 48×48 이미지로 변환하려 했으나 **결과물이 전부 흰 이미지**로 나왔습니다.

이전 README는 원인을 *"이모지 원본 이미지가 기업 자산(라이선스 소유물)이라 정제된 데이터셋을
구하기 어려웠다"* 로 적었습니다. **그러나 실제 코드를 보면 라이선스와 무관합니다.**

```python
for i, emoji in enumerate(selected_data):
    emoji_image = Image.new('RGB', (48, 48), color='white')   # 흰 배경 생성
    emoji_draw  = ImageDraw.Draw(emoji_image)                 # draw 객체 생성

    # ← 여기에 emoji_draw.text(...) 로 이모지를 그리는 코드가 없음

    emoji_image.save(f"{output_directory}/emoji_{i+1}.png")   # 흰 이미지 그대로 저장
```

`ImageDraw.Draw()` 객체를 만들기만 하고 **`draw.text()` 호출이 빠져 있습니다.**
이모지를 그리는 단계 자체가 없으니 흰 이미지가 나오는 것이 당연한 결과입니다.

→ 실제 원인은 **코드 누락**입니다. 라이선스는 별개 이슈입니다.

### ✅ 이 버그는 수정했습니다 (2026-09-10)

`학습이력_분석_및_이모지변환_수정.ipynb`에서 실제로 고쳐 실행했습니다.

  받지 않습니다 — 137px는 `invalid pixel size` 오류)
- `textbbox()`로 글리프 위치를 보정
- **결과: 105개 전부 정상 변환** (원본 방식은 픽셀 최소/최대가 255/255로 흰 이미지가 그대로 재현됨)

### 그런데 이 실험은 애초에 성립하지 않았습니다

버그를 고쳤어도 이모지를 모델에 넣는 단계는 진행할 수 없습니다. 두 가지 이유입니다.

**첫째, 학습된 가중치가 없습니다.** 원본 노트북에 `model.save()` 호출이 없어
**모델이 Colab 세션과 함께 사라졌습니다.**

**둘째, 가중치가 있어도 결과에 의미가 없습니다.** 형식만 48×48 그레이스케일로 같을 뿐 내용이 다른 분포입니다.

| | 학습 데이터 (FER) | 이모지 입력 |
| --- | --- | --- |
| 대상 | 사람 얼굴 사진 | 양식화된 그림 |
| 촬영 조건 | 자연광·다양한 각도/조명 | 균일한 흰 배경 |
| 픽셀 분포 | 연속적인 명암 계조 | 평탄한 색면 + 뚜렷한 윤곽 (순백 픽셀 26.3%) |
| 규모 | 22,968장 | 105장 |

사람 얼굴에서 학습한 필터가 이런 입력에서 의미 있는 특징을 뽑을 이유가 없습니다.

### 그리고 애초에 모델이 필요 없었습니다

이모지에 CNN을 돌려서 얻으려던 감정 레이블은 **`emoji_df.csv`의 `name` 칸에 이미 있었습니다.**

```
😠 angry face        😨 fearful face       😢 crying face
😐 neutral face      😲 astonished face    🤢 nauseated face
```

FER 7개 클래스의 이름이 그대로 들어 있습니다. 필요한 것은 모델이 아니라 **대응표**였습니다.

원본이 선택한 `iloc[0:105]`도 임의의 숫자가 아니었습니다. 105개가 전부 `face-` sub_group이고,
잘라낸 자리 뒤(105~118)는 🤬😈👿💀☠️ 와 💩🤡👹👺👻👽👾🤖 — 해골·악마·광대·유령·외계인·로봇처럼
**사람의 표정이 아닌 얼굴**이며, 119번부터는 고양이 얼굴(😺)이 시작됩니다.
즉 **사람 표정 이모지만 골라낸 선택**이었습니다.

**데이터를 고른 판단은 처음부터 옳았습니다. 갈린 것은 그 데이터를 쓰는 방법이었습니다.**

→ 자세한 내용과 완성된 매칭 파이프라인은 [`이모지_매칭_파이프라인.ipynb`](이모지_매칭_파이프라인.ipynb) 참고.

## 3단계 완성 — 감정 벡터에서 이모지로

### ① 감정 수치화는 이미 되어 있었습니다

2단계 "감정을 수치화한다"는 사실 1단계에서 끝나 있었습니다. 원본 추론 코드입니다.

```python
predictions = model.predict(img_array)                   # ← 7차원 확률 벡터
predicted_label = class_labels[np.argmax(predictions)]   # 최대값 위치만 꺼냄
confidence = predictions[0][np.argmax(predictions)]      # 최대값만 꺼냄
```

`predictions[0]`이 7개 클래스의 확률 벡터입니다. 그런데 코드는 `argmax`로 하나만 꺼내고
**나머지 6개를 버렸습니다.** 버려진 그 벡터가 바로 감정 수치화였고, 새로 만들 것이 없었습니다.

### ② 이모지 대응표 — 105개 중 54개

`name` 키워드로 매핑했습니다. `sub_group`은 FER 클래스와 경계가 맞지 않습니다
(`face-concerned` 27개가 sad·fearful·surprised 셋에 걸쳐 있고, `face-unwell` 12개는 대부분 감정이 아닙니다).

| 클래스 | 개수 | 예시 |
| --- | --- | --- |
| happy | 21 | 😀 😄 😁 🤣 😊 🥰 😎 |
| sad | 16 | 😢 😭 😞 🥺 ☹️ 😔 |
| fearful | 4 | 😨 😰 😧 😱 |
| surprised | 4 | 😮 😯 😲 😳 |
| neutral | 4 | 😐 😑 😶 🫥 |
| angry | 3 | 😠 😡 😤 |
| disgusted | 2 | 🤢 🤮 |

**51%(54/105)만 매핑됩니다. 이것은 실패가 아니라 결과입니다.**
나머지 51개는 FER 7개 클래스로 표현할 수 없습니다 — 감정이 아니거나(🤔 thinking, 😴 sleeping,
😷 medical mask), 7개 밖의 감정이거나(😏 smirking, 😒 unamused, 🙄 rolling eyes)입니다.
**이모지 목록이 7개 클래스 모델보다 표현력이 넓다**는 것이 원래 설계의 한계를 보여줍니다.

### ③ 매칭 규칙

1. 벡터의 최대 클래스를 고름
2. 그 클래스 안에서 **모델의 확신도와 이모지 강도가 가장 가까운** 것을 고름
   (강도는 이름의 수식어로 부여 — `slightly` 0.3 / 기본 0.6 / `loudly`·`beaming`·`enraged` 0.9)

확신도가 높으면 센 이모지(😁 🤣), 낮으면 약한 이모지(🙂)가 뽑힙니다.

| 입력 감정 벡터 (예시) | 최대 클래스 | 확신도 | 할당 |
| --- | --- | --- | --- |
| 아주 밝게 웃는 얼굴 | happy | 0.92 | 😁 |
| 화난 얼굴 | angry | 0.78 | 😡 |
| 우는 얼굴 | sad | 0.88 | 😭 |
| 놀란 얼굴 | surprised | 0.71 | 😮 |
| 무표정 | neutral | 0.64 | 🫥 |

> 위 벡터는 규칙 검증용으로 **손으로 지정한 값**입니다. 모델 출력이 아닙니다(가중치 소실).

### ④ 이 파이프라인의 진짜 한계 — 확신도 0.28

원본이 실제 사진에 대해 낸 확신도는 **0.28**이었습니다. 7개 클래스에서 최대가 0.28이면
나머지에 0.72가 흩어져 있다는 뜻입니다. 그 벡터에 잡음을 넣어 최대 클래스가 얼마나 바뀌는지 쟀습니다.

| 잡음 표준편차 | 클래스가 바뀐 비율 (확신도 0.28) | 비교 (확신도 0.85) |
| --- | --- | --- |
| 0.02 | 0.0% | — |
| 0.05 | 7.1% | — |
| 0.10 | **41.9%** | **0.0%** |

**확신도가 낮으면 할당 결과가 사실상 임의가 됩니다.** 이것은 매칭 규칙의 결함이 아니라
1단계 모델 정확도(0.5628)가 그대로 전파된 것입니다.
**파이프라인의 품질 상한은 표정 분류 모델이 결정합니다.**

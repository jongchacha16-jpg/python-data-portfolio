# 레드 와인 품질 회귀분석 (Wine Quality Regression)

레드 와인의 이화학적 특성(산도, 당도, 밀도, 알코올 등)으로 관능 평가 점수인 품질(`quality`)을
설명할 수 있는지 확인하는 회귀분석 팀 프로젝트입니다.

목표는 예측 정확도를 높이는 것보다 **회귀분석의 가정을 제대로 점검하는 것**이었습니다.

## 데이터

| 항목 | 내용 |
| --- | --- |
| 출처 | UCI Machine Learning Repository — Wine Quality Dataset |
| 규모 | 레드 와인 **1,599행 × 12열** (화이트 와인 4,898행도 비교용 확보) |
| 타겟 | `quality` (관능 평가 점수, 실제 관측 범위 3~8) |
| 설명변수 11개 | fixed/volatile acidity, citric acid, residual sugar, chlorides, free/total sulfur dioxide, density, pH, sulphates, alcohol |

**타겟 분포가 중간 등급에 극단적으로 몰려 있습니다.**

| quality | 3 | 4 | 5 | 6 | 7 | 8 |
| --- | --- | --- | --- | --- | --- | --- |
| 개수 | 10 | 53 | **681** | **638** | 199 | 18 |

5·6등급이 전체의 **82.5%**이고 양 극단은 표본이 거의 없습니다. 이 불균형이 모델 성능의 상한을 결정했습니다.

## 접근 방법

1. 설명변수 간 상관행렬로 다중공선성 진단 — `density`와 `residual sugar`·`fixed acidity`의 높은 상관 확인
2. 전체 설명변수를 넣은 기본 OLS 적합
3. **변수를 하나씩 제거하며 남은 회귀계수의 신뢰도 변화를 관찰**
4. 잔차 플롯으로 선형성·등분산성 검토
5. 표본이 극히 적은 3·4등급(합계 63개) 제거 실험
6. 화이트/레드/통합 케이스 비교

### 변수 제거 실험 결과

| 제거한 변수 | 관찰 결과 | 판단 |
| --- | --- | --- |
| `total sulfur dioxide` | 제거를 고려할 만하나 R²가 더 낮아짐 | 보류 |
| `density` | `fixed acidity`·`residual sugar`의 설명력 신뢰성 저하 | 제거 시 부작용 |
| `pH` | 남은 회귀계수의 신뢰수준 유지 | **제거 가능** |
| `sulphates` | 다른 회귀계수에 영향을 줌 | 유지 |
| `alcohol` | 삭제하지 않는 것이 맞음 | 유지 |

## 결과

**전체 변수 OLS (레드 와인 1,599건 전수)**

| 지표 | 값 |
| --- | --- |
| R-squared | **0.361** |
| Adj. R-squared | 0.356 |
| F-statistic | 81.35 (Prob < 1.79e-145) |
| 관측치 수 | 1,599 |

**학습/테스트 분할 선형회귀** (`test_size=0.2`): MSE **0.390**, R² **0.403**

**회귀계수 — 품질에 영향이 큰 변수**

| 변수 | 계수 | 방향 |
| --- | --- | --- |
| density | **−10.35** | 밀도가 높을수록 품질 ↓ |
| chlorides | −1.81 | 염화물이 많을수록 품질 ↓ |
| volatile acidity | −1.00 | 휘발성 산도가 높을수록 품질 ↓ |
| sulphates | +0.84 | 황산염이 많을수록 품질 ↑ |
| alcohol | +0.28 | 도수가 높을수록 품질 ↑ |

**결론**: 이화학적 성분만으로는 품질 변동의 **약 36~40%만 설명**됩니다. 관능 평가에는 향·목넘김 등
측정되지 않은 요인이 크게 작용하며, 타겟이 5·6등급에 82.5% 몰려 있어 선형모델이 잡아낼 수 있는
변동 자체가 제한적입니다.

## ⚠️ 결과에서 제외한 수치

`wine.ipynb`에 랜덤포레스트 회귀 결과가 **MSE 0.0 / R² 1.0**으로 기록되어 있으나,
**같은 셀의 특성 중요도가 11개 변수 전부 0.0**이었습니다.

트리가 분기를 전혀 하지 않았는데 완벽히 예측했다는 것은 성립할 수 없으므로,
셀 실행 순서로 데이터가 어긋난 상태에서 나온 **무효한 출력**으로 판단해 결과에서 제외했습니다.
성능 지표 하나만 보고 "랜덤포레스트가 훨씬 우수하다"고 결론 냈다면 잘못된 보고가 됐을 것입니다.

## 파일 구성

- `Red_Wine(박찬종).ipynb` — 담당 분석 파트 (변수 변환·선택·잔차 분석)
- `Red_wine(변수 변환,변수 선택,잔차 분포도).ipynb` — 변수 변환/선택 실험
- `wine.ipynb`, `residuals.ipynb` — 모델링 및 잔차 진단 실험
- `보고서 작성자료(wine).ipynb` — 팀 보고서용 정리 자료

> 원본 데이터는 저장소에 포함하지 않았습니다. [UCI Wine Quality Dataset](https://archive.ics.uci.edu/dataset/186/wine+quality)에서 받을 수 있습니다.

## 배운 점

- **변수 선택의 기준은 성능이 아니라 "남은 계수를 믿을 수 있는가"였습니다.** R²만 보고 변수를 빼면
  `density`처럼 다른 변수의 설명력을 무너뜨리는 경우를 놓칩니다.
- **R² 0.36은 낮은 것이 아니라 이 데이터로 가능한 수준이었습니다.** 타겟의 82.5%가 두 등급에 몰려 있으면
  설명할 수 있는 변동 자체가 작습니다. 성능 수치는 데이터 구조와 함께 읽어야 합니다.
- **완벽한 성능 지표는 성과가 아니라 경고 신호입니다.** 특성 중요도가 전부 0이라는 모순을 함께 확인했기에
  무효한 결과를 걸러낼 수 있었습니다.
- **정수형 타겟에 선형회귀를 쓰는 구조적 한계**를 체감했습니다. `quality`는 3~8의 이산 등급이라
  잔차가 계단 형태로 나타납니다. 순서형 로지스틱 회귀 같은 대안을 고려했어야 했습니다.

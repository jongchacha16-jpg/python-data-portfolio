# 표정 분류 CNN 모델 (Facial Expression Recognition)

얼굴 표정 이미지를 7개 감정으로 분류하는 CNN 모델입니다.

> **⚠️ 이 README는 2026-09-07에 정정되었습니다.**
> 이전 README는 이 프로젝트를 *"기한 내 목표를 완전히 달성하지 못했다 / 모델 학습까지 완료하지 못했다"*
> 고 서술했으나, **노트북을 실제로 열어 확인한 결과 모델은 완성되었고 20에폭 학습까지 끝나 있었습니다.**
> 실패한 것은 부가 시도였던 이모지 변환 하나였고, 그 실패 원인 진단도 틀렸습니다(아래 §실패한 부분 참고).

## 데이터

| 항목 | 내용 |
| --- | --- |
| 출처 | Kaggle — [`ananthu017/emotion-detection-fer`](https://www.kaggle.com/datasets/ananthu017/emotion-detection-fer) |
| 규모 | 훈련 **22,968장** / 검증 **1,432장** |
| 클래스 | 7개 — `angry`, `disgusted`, `fearful`, `happy`, `neutral`, `sad`, `surprised` |
| 형식 | 48×48 그레이스케일 |

증강: `shear_range=0.2`, `zoom_range=0.2`, `horizontal_flip=True`, 정규화 `1./255`

## 모델

```
Conv2D(32, 3×3, relu) → MaxPool(2×2)
Conv2D(64, 3×3, relu) → MaxPool(2×2)
Conv2D(128, 3×3, relu) → MaxPool(2×2)
Flatten → Dense(256, relu) → Dropout(0.5) → Dense(7, softmax)

optimizer=adam, loss=categorical_crossentropy, epochs=20
```

## 결과

| 지표 | 값 |
| --- | --- |
| 최종 검증 정확도 | **0.5628** |
| 최고 검증 정확도 | 0.5656 (에폭 17) |
| 최종 훈련 정확도 | 0.5705 |
| 무작위 기준선 (7클래스) | 0.1429 |
| 개선 배수 | **약 3.9배** |

학습 추이: 훈련 정확도 0.2869 → 0.5705, 검증 정확도 0.3876 → 0.5628

**학습 곡선에서 읽히는 것**

1. **과적합이 거의 없습니다.** 최종 훈련-검증 정확도 격차가 **+0.0077**에 불과합니다.
   `Dropout(0.5)`와 데이터 증강이 제 역할을 한 것으로 보입니다.
2. **평탄 구간에 들어갔습니다.** (2026-09-10 정정 — 아래 참고)

> ### ⚠️ "에폭이 부족하다"는 서술을 정정합니다 (2026-09-10)
>
> 이 README는 원래 *"검증 손실이 마지막 20에폭에서 최저(1.1655)를 기록했으므로 에폭이 부족한
> 상태이며, 더 학습하면 개선 여지가 있다"* 고 적었습니다.
> **20에폭 로그 전체를 정량 분석한 결과 이 결론은 데이터로 지지되지 않습니다.**
>
> | 항목 | 실측 |
> | --- | --- |
> | val_loss 곡선 | 단조 감소가 아니라 **6개 에폭에서 상승**(8·12·14·16·18·19)하는 진동 곡선 |
> | 20에폭 최저값의 정체 | 1.1738 → 1.2112 → **1.2333** → 1.1655 — **두 에폭 상승 뒤의 반등** |
> | 검증 정확도 정점 | **에폭 17에서 0.5656 최고** 후 하락 (최종 0.5628) |
> | 마지막 5에폭 기울기 | val_acc **−0.00106/에폭**, val_loss **+0.00191/에폭** |
> | 개선 속도 | 후반 10에폭이 전반의 **22%** 수준 (+0.0161 → +0.0036/에폭) |
>
> 마지막 한 점만 보고 판단했던 것이 원인입니다. 모델은 **에폭 13~17에서 이미 0.54~0.57 대에 정체**했고,
> 20에폭의 val_loss 최저값은 진동 속의 한 점입니다.
> 정확도를 올리려면 에폭을 늘리는 것이 아니라 학습률 스케줄링·구조 변경 등 다른 요인을
> 건드려야 합니다(이 부분은 `[미검증]`).

**실제 이미지 추론**: 외부 이미지(`happy.jpg`)로 예측했을 때 `happy`로 맞혔으나
**확신도는 0.28**이었습니다. 7클래스 중 최고 확률이 0.28이라는 것은 클래스 간 구분이
뚜렷하지 않다는 뜻이므로, 정확도 56%와 함께 읽어야 합니다.

## 실패한 부분 — 이모지 변환 (그리고 원인 진단의 오류)

원래 구상은 학습한 모델을 **이모지 이미지**에도 적용해보는 것이었습니다.
이모지를 48×48 이미지로 변환하려 했으나 **결과물이 전부 흰 이미지**로 나왔습니다.

이전 README는 원인을 *"이모지 원본 이미지가 기업 자산(라이선스 소유물)이라 정제된 데이터셋을
구하기 어려웠다"* 로 적었습니다. **그러나 실제 코드를 보면 라이선스와 무관합니다.**

```python
for i, emoji in enumerate(selected_data):
    emoji_image = Image.new('RGB', (48, 48), color='white')   # 흰 배경 생성
    emoji_draw  = ImageDraw.Draw(emoji_image)                 # draw 객체 생성

    # ← 여기에 emoji_draw.text(...) 로 이모지를 그리는 코드가 없음

    emoji_image.save(f"{output_directory}/emoji_{i+1}.png")   # 흰 이미지 그대로 저장
```

`ImageDraw.Draw()` 객체를 만들기만 하고 **`draw.text()` 호출이 빠져 있습니다.**
이모지를 그리는 단계 자체가 없으니 흰 이미지가 나오는 것이 당연한 결과입니다.

→ 실제 원인은 **코드 누락**입니다. 라이선스는 별개 이슈입니다.

### ✅ 이 버그는 수정했습니다 (2026-09-10)

`학습이력_분석_및_이모지변환_수정.ipynb`에서 실제로 고쳐 실행했습니다.

- 컬러 이모지 폰트(`Apple Color Emoji.ttc`)를 지정하고 **빠져 있던 `draw.text()` 호출을 추가**
- 160px로 렌더링 후 48px로 `LANCZOS` 축소 (Apple Color Emoji는 비트맵 기반이라 임의 크기를
  받지 않습니다 — 137px는 `invalid pixel size` 오류)
- `textbbox()`로 글리프 위치를 보정
- **결과: 105개 전부 정상 변환** (원본 방식은 픽셀 최소/최대가 255/255로 흰 이미지가 그대로 재현됨)

### 그런데 이 실험은 애초에 성립하지 않았습니다

버그를 고쳤어도 이모지를 모델에 넣는 단계는 진행할 수 없습니다. 두 가지 이유입니다.

**첫째, 학습된 가중치가 없습니다.** 원본 노트북에 `model.save()` 호출이 없어
**모델이 Colab 세션과 함께 사라졌습니다.**

**둘째, 가중치가 있어도 결과에 의미가 없습니다.** 형식만 48×48 그레이스케일로 같을 뿐 내용이 다른 분포입니다.

| | 학습 데이터 (FER) | 이모지 입력 |
| --- | --- | --- |
| 대상 | 사람 얼굴 사진 | 양식화된 그림 |
| 촬영 조건 | 자연광·다양한 각도/조명 | 균일한 흰 배경 |
| 픽셀 분포 | 연속적인 명암 계조 | 평탄한 색면 + 뚜렷한 윤곽 (순백 픽셀 26.3%) |
| 규모 | 22,968장 | 105장 |

사람 얼굴에서 학습한 필터가 이런 입력에서 의미 있는 특징을 뽑을 이유가 없습니다.
**고친 것은 "흰 이미지만 나온다"는 버그이고, 실험 자체는 여전히 열려 있습니다.**

## 알려진 한계

1. **학습된 가중치가 남아 있지 않습니다.** 원본 노트북에 `model.save()` 호출이 없어
   모델이 Colab 세션과 함께 사라졌습니다. 남은 것은 학습 로그뿐입니다.
2. **원본은 Colab 전용입니다.** 데이터 경로가 `/content/`, Google Drive 마운트에 의존합니다.
   (재분석 노트북은 로컬에서 실행됩니다.)
3. **정확도 56%는 높은 수준이 아닙니다.** 에폭을 늘리는 것으로는 개선되지 않을 가능성이 큽니다(위 정정 참고).
4. **클래스별 성능을 확인하지 못했습니다.** 혼동 행렬을 만들려면 검증셋 1,432장과 가중치가 모두 필요한데
   둘 다 없습니다.

**진행하려면 필요한 것**: 아래 세 가지는 Kaggle API 토큰과 TensorFlow 설치가 있으면 가능합니다.

| 하려던 것 | 막힌 이유 |
| --- | --- |
| 혼동 행렬 · 클래스별 정확도 | 검증셋 + 가중치 둘 다 없음 |
| 에폭·구조를 바꾼 재학습 | Kaggle 데이터셋(24,400장) + TensorFlow 필요 |
| 이모지에 모델 적용 | 가중치 없음 + 도메인 불일치로 의미 없음 |

## 배운 점

- **"코드가 에러 없이 돌았다"와 "결과가 올바르다"는 다릅니다.** 이모지 변환은 예외 하나 없이
  완료됐지만 산출물은 전부 흰 이미지였습니다. 중간 산출물을 눈으로 확인하는 단계가 없으면
  이런 실패는 마지막에야 드러납니다.
- **실패 원인을 잘못 진단하면 잘못된 교훈이 남습니다.** "라이선스 문제였다"고 정리해두면
  다음에도 같은 코드 실수를 반복하게 됩니다. 원인은 코드에서 확인해야 합니다.
- **문서가 프로젝트를 실제보다 낮게 평가할 수도 있습니다.** 이 README를 정정하기 전까지
  완성된 모델이 "실패 사례"로 기록되어 있었습니다.
- **곡선의 마지막 한 점으로 수렴을 판단하면 안 됩니다.** "val_loss가 마지막 에폭에서 최저"는
  사실이지만, 그 앞 두 에폭이 상승 중이었다는 것을 빼고 말하면 **정반대 결론**이 나옵니다.
  추세는 점이 아니라 구간으로 봐야 합니다.
- **학습이 끝난 모델은 저장해야 존재합니다.** `model.save()` 한 줄이 없어서
  22,968장으로 약 18분간 학습한 결과가 남지 않았습니다.
- **버그를 고치는 것과 실험이 성립하는 것은 다른 문제입니다.** `draw.text()` 누락은 진짜 버그였고
  실제로 고쳤지만, 고치고 나서 보니 **사람 얼굴로 학습한 모델을 이모지에 적용한다는 발상 자체가
  성립하지 않았습니다.** 당시에는 코드가 막혀서 이 지점까지 오지 못했습니다.
